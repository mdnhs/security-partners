# Careers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/careers`, `/careers/<slug>` and `/careers/<slug>/apply`, built from Figma and run entirely from the admin panel (page copy, jobs, applications with CVs).

**Architecture:** Page copy is a new fixed page `careers` (template `careers`) in the existing page system. Jobs are a versioned entity shaped like `services` (draft/publish/revisions/slug + 301). Applications are a lead-like entity with private file storage, a multipart public endpoint guarded like `/public/leads`, an admin inbox and a retention job.

**Tech Stack:** Next.js 16 (cacheComponents; read `node_modules/next/dist/docs/` before route work), Hono API, Drizzle/Postgres, zod, TanStack Query, Tailwind v4, GSAP hooks in `components/motion/page-story.ts`, Vitest (unit, dom, integration), Playwright e2e. Figma via the `figma-desktop` MCP.

**Spec:** `docs/superpowers/specs/2026-11-04-careers-design.md`

## Global Constraints

- Work on branch `feat/dynamic-platform`; commit after every task; `main` only by merging this branch when the user asks.
- Every public string comes from the careers page, the job or settings; components hold none.
- Open = published && !filled && closingDate >= today in `Europe/Dublin` (`lib/format.ts` `SITE_TIME_ZONE`).
- Uploads: CV `application/pdf`, `application/msword`, `application/vnd.openxmlformats-officedocument.wordprocessingml.document`, ≤ 5 MB, required; PSA card `image/jpeg`, `image/png`, `application/pdf`, ≤ 5 MB, optional. Type by sniffing bytes.
- Public submit: rate limit 5 per 10 minutes per IP (bucket `careers`), honeypot field `website`, Turnstile via the leads `assertHuman` path.
- Application files live under storage keys `applications/<applicationId>/<cv|psa-card>.<ext>`; never a `media` row.
- Statuses: `new`, `reviewing`, `shortlisted`, `interview`, `offered`, `hired`, `rejected`.
- Permissions: `job: read/create/update/publish/delete` (owner, admin, editor; marketer, viewer read); `application: read/update/delete` (owner, admin; intake read/update).
- Mobile: no horizontal overflow at 320–768 px, CTAs full width below `sm`, layout identical with motion on/off (the checks used for the site already).
- Frozen-hash fixture `tests/unit/blocks/frozen-components.json`: refresh only files you changed.

## Review Focus

1. A closed or filled job reached by an old link (detail, apply, API) — shows the closed notice, never accepts an application; a test per surface (Tasks 3, 5, 6).
2. A renamed CV (`virus.exe` called `cv.pdf`, an HTML file called `.docx`) — refused by sniffing with a field error on `cv` (Task 5).
3. A visitor double-clicking Submit or retrying after a network drop — one application per submission token, not two (Task 5: `submissionId` uuid in the form, unique column).
4. An applicant's files after a delete or the retention purge — gone from storage too, and the download route 404s (Task 5, Task 7).
5. The careers page or a job edited to an empty list (no open jobs, no benefits, no previous openings) — the section shows its empty copy or disappears, never an empty card grid (Tasks 3, 4).

# MK Parity Implementation Plan (Master)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the Security Partners admin to Magda Kennedy (MK) parity in look, IA and features, keeping SP brand colours and draft/publish, without moving a single public pixel.

**Architecture:** Same app and layering as the base platform: `app/(admin)/admin`, Hono under `server/api`, routes → service → repo, isomorphic `lib/`. Phase A makes the admin CSS self-contained and MK-styled. Phase B moves the IA to a single nav registry (`lib/admin/nav.ts`) that drives the sidebar, rails, ⌘K and page guards. Phase C adds a pure theme engine (`lib/theme/*`) stored as settings key `theme`, plus AI parity. Phase D adds the feature work in five sub-phases. New public capability lands only behind defaults that render nothing (`/p/<slug>` builder pages, `/newsletter/*`, theme `<style>`, newsletter placement).

**Tech Stack:** Next.js 16.3.8, React 19.3, TypeScript 5.9 strict, Tailwind 4.3, shadcn base-nova on `@base-ui/react` 1.9.0, Hono 4.13, Better Auth 1.7.10, Drizzle 0.45.4, Zod 4.6.7, TanStack Query 5 / Table 9, react-hook-form 7.90, dnd-kit 6/10, AI SDK `ai` 7.0.127. New deps: `culori@4.0.2`, `@types/culori@4.0.1`, `react-colorful@5.8.1`, `@ai-sdk/google` 4.0.x, `@ai-sdk/openai-compatible` 3.0.x (newest qualifying versions). Tests: Vitest 5 (projects `unit`, `dom`, `integration`) and Playwright 1.64.

## Review Focus

1. **Seeded public site after every public-adjacent change.** If a theme `<style>`, a newsletter placement, a verification `<meta>`, a page-view push or a builder route leaks into the 20 public URLs, it is a regression. Pinned by:
   - C3: a DOM/integration test that the default theme renders no `#site-theme`;
   - D4.2: a unit test that `placement:"off"` renders `null`;
   - D1.6: a test that empty verification emits no `verification`;
   - the public visual gate on every public-adjacent task.
2. **Old admin bookmarks and links** (`/admin/articles/123`, `/admin/audit?actor=…`, `/admin/marketing/tracking`) must land on the new screen with the query kept, not on a 404 or a forbidden page. Pinned by B2/B3 unit tests on `ADMIN_LEGACY_REDIRECTS` and an e2e that visits every old path, plus a repo grep gate for old hrefs.
3. **A role that lost or never had a permission reaching a moved page directly by URL** (viewer at `/admin/marketing/code`, marketer at `/admin/appearance` with read-only, editor at `/admin/settings/ai-assistant`) must get the forbidden page or a read-only UI, never an editable form. Pinned by:
   - B5's fs-scan test (every panel page calls `requirePage`);
   - C5/C7 role e2e;
   - D2.3's owner-only tests.
4. **Two people editing the same draft** must get a 409 and a conflict dialog, never a silent overwrite. Affected drafts: theme, a builder page, a newsletter setting. Pinned by integration tests with a stale `version` in C2, D4.1 and D5.2, and the dialog DOM test in C5/D5.5.
5. **Hostile or messy input on new free-text surfaces** must be rejected with a field error, never stored raw or rendered as HTML:
   - colour strings (`red; } body {`)
   - CSV imports (`=cmd()` formulas, BOM, CRLF, quoted commas, 5 000 rows)
   - AI markdown (`<script>`, `javascript:` links)
   - snippet routes or hosts
   - newsletter emails with uppercase or whitespace
   
   Pinned by: C1 `parseColor` tests, D1.8 CSV parser and import tests (incl. a formula-injection guard on export), C9 markdown tests, D2.3 snippet schema tests, D4.1 email normalisation test.

## Rulings that override this plan (2026-10-20)

Decisions taken during execution. Where a task above says otherwise, the
ruling wins. Source: the controller's ledger
(`.superpowers/sdd/2026-10-19-mk-parity/progress.md`, line numbers in
brackets) and the final whole-branch review.

- **Newsletter confirm is a POST page, not a GET** (L88). The emailed
  link opens `/newsletter/confirm`, whose button POSTs the token;
  `GET /api/v1/public/newsletter/confirm` only redirects there (mail
  gateways pre-fetch links). Unsubscribe works the same way.
- **Newsletter settings are owner/admin only** (L165). Editors lose the
  toggle the plan gave them; `newsletter:read`/`export` for marketers is
  unchanged (the "all" export is owner/admin only, L88).
- **Lead attribution is consent-gated** (L160). First touch is stored in
  `sessionStorage` only with analytics consent (Irish ePrivacy), cleared on
  refusal or withdrawal, and the contact form sends it only with analytics
  consent. With tracking off nothing is stored.
- **Invalid attribution never loses a lead** (L167, M5). The server drops
  an invalid value (warns `[leads] invalid attribution dropped; enquiry
  kept`) and saves the enquiry with 200, instead of the plan's 422.
- **`twitter:title` = the social title** (L120), so the card is
  consistent with `og:title`.
- **Builder drafts need `page:read` in the preview session** (L114).
  Authors cannot preview builder drafts. Fixed-page drafts keep the coarse
  model (any previewer sees them), accepted (L148).
- **Builder reserved anchors** (L106, L134): `about`, `services`, `team`,
  `blog`, `contact` cannot be block anchors, enforced in the UI and
  server-side in `validateDocument`.
- **Lead status is last-write-wins** (L193), as the pre-existing API.
- **Every public page uses `SiteThemed`**, never a bare `Suspense` (L123):
  per page, so real 404s keep their status.
- **Owner "share enquiry details" acknowledgement resets** when the AI
  provider or OpenAI-compatible base URL changes (L122). Staff names and
  bylines may reach the provider (L179); the Settings › Leads record (staff
  notification addresses) does not (final review minor 6).
- **Legacy AI messages are treated as holding enquiry details** (L195), so
  switching sharing off never re-sends old history.
- **Newsletter `?token` is stripped with `replaceState` after load**
  (L130).
- **Custom code** (L3 ruling 4): legacy blocks became `necessary`
  all-routes snippets; a DB kill switch plus `pnpm custom-code:off`.
  Route scope is checked in the browser at run time and on client
  navigation (L144).
- **Mailpit e2e round trip is skipped when Mailpit is not reachable on the
  LAN address** (L49); the dev compose keeps its loopback bind.
